# Самотесты ядра

Один бинарь без фреймворка: `ferry-core-test` печатает, что проверил, и
возвращает ненулевой код при первом расхождении.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target ferry-core-test
./build/tests/ferry-core-test
```

Что здесь на самом деле важно:

- **Векторы BLAKE3** из официального репозитория. Всё остальное ядро можно
  переписать и заметить ошибку по поведению; хеш так проверить нельзя —
  неправильная реализация стабильно даёт стабильно неправильный ответ, и
  разойдёмся мы с миром только тогда, когда кто-то напишет второй клиент.
- **Вектор HKDF из RFC 5869.** Та же логика: вывод ключей должен совпадать
  с тем, что сделает WebCrypto в браузере, иначе веб-клиент из M3 не
  расшифрует ничего из того, что отправил CLI.
- **AAD в AEAD.** Три отдельные проверки на то, что подмена индекса чанка,
  подмена общего числа чанков (атака обрезания) и чужой ключ отвергаются.
- **Санитизация путей** (§3 проектного документа, класс Zip Slip).
- **Сквозной проход** без сети: отправитель шифрует, получатель принимает
  чанки в обратном порядке (как при двух волнах), проверяет каждый по
  списку хешей и собирает том побайтово.

# Сценарные проверки

`scenarios.sh` поднимает релей и двух клиентов на одной машине и проверяет то,
что складывается из ядра: реальный перевоз, веер на двоих, отказы, одноразовую
ссылку и докачку после обрыва.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build
cmake -S Server -B build-server -DCMAKE_BUILD_TYPE=Release && cmake --build build-server
./tests/scenarios.sh
```

Нужны `curl`, `jq`, `sha256sum` и около 7 ГБ свободного места под `/tmp`.

Почему сценарий с докачкой берёт том на 5 ГиБ, а не сто мегабайт: на меньшем
томе перевоз по петле успевает закончиться раньше, чем тест успевает его
прервать, и докачка остаётся непроверенной. Заодно это единственный размер,
на котором включается чанк в 4 МиБ, — то есть проверяется и он.

Что здесь проверяется помимо очевидного:

- **превью-бот не жжёт использование.** Четыре обращения к
  `GET /api/transfers/<id>` не трогают счётчик: ссылку в мессенджере
  открывает бот, и одноразовая раздача не должна умирать от этого;
- **чужой ключ отвергается на манифесте**, то есть до того, как на диске
  появится хоть один байт;
- **ссылка без ключа** объясняет человеку, что произошло, а не падает.
